## Integration

Import `ContentEditor` from `apps/workspaces/src/content/ContentEditor.tsx`. Pass `locale` (EN/ML/TA), the shared session `Resource<unknown>`, optionally `readRecord: (signal: AbortSignal) => Promise<Resource<unknown>>`, and optionally `authoring: ContentAuthoringPort` from `content/authoring-port.ts`. A ready read contains one existing `KnowledgeRecord`, or `null` for empty. The owner must provide a current scoped authorized read. Without a reader, presentation is Pending. Without an authoring port, every mutation remains disabled/Pending. No root route is wired.

The session schema and `workspaceAccess` only gate staff/physician workspace presentation. They do not grant editor, approver, physician qualification or record access. The backend must enforce current identity, company scope and ownership on every read/mutation. No client role selection is an authorization mechanism.

Strict shared knowledge schemas reject extra fields, invalid provenance URLs, malformed revisions, approval/hash mismatches, self-approval (including UUID aliases) and invalid withdrawal chronology. Supplied lifecycle labels are expressly **not current publication authorization**. Schema parsing does not verify source-object bytes, recompute canonical hashes or establish current approval authority. The future authoritative adapter must implement those checks plus version/CAS/audit/withdrawal guarantees; this UI cannot replace them.

Draft records permit bounded local title/text edits (200/16000 code units, nonblank). The default remains local scratch only; with a validated explicit edit grant and complete pre-reviewed public source bytes, Save creates a **new chained revision**, never an in-place edit. Explicit edit authority may also create a new draft from an approved/withdrawn record; the supplied historical text remains unchanged. Approval/withdrawal require their own current scoped grants. A staff grant or a distinct physician workspace never enables approval. Recorded editor and named approver are displayed separately; the current editor receives an explicit canonical UUID self-approval denial.

Reads time out after five seconds, abort on replacement/unmount, fence late completions and hide old content on loading/error/invalid/denied/empty/pending outcomes. Refresh, session identity/expiry/**workspace-grant** change, authoring-port replacement, revoked presentation access, page hiding/restoration and backgrounding discard local drafts at the render boundary. After lifecycle suspension an explicit refresh is required. No storage, analytics, raw errors, generated answers or automatic mutation retries exist. Parent session integration still owns actual session refresh/revocation detection.

## Canonical authoring HTTP integration — required root transport

`ContentAuthoringPort` is a trusted integration seam, **not a new server permission matrix or wire grant schema**. It requires:

- `readSource(context, signal)` and a mandatory `decodeSource(raw)` implemented by the backend owner against the **actual exact current-authority source contract**. No default decoder, role fallback, made-up source route, local physician qualification or artificial grant expiry is supplied.
- The decoder projects its verified source into the internal `SourceAuthorization` view: existing `KnowledgeAuthorityActor`, full existing `KnowledgeRecord`, one existing lifecycle permission (`edit`, `approve`, `withdraw`), and actual source expiry. The UI validates these shared schemas and requires canonical actor equality with the current session, exact record/content/scope/language/version/hash equality, exact requested permission, and unexpired source/session. It denies alias self-approval independently. The actual source codec must establish current qualification, grant evidence/version and approved scope; mapping workspace roles or returning invented grants is not a valid adapter.
- `submit(command, signal)` returns the trusted HTTP wrapper `{httpStatus, body}`. `authoringRequest(command)` in `content/authoring-dto.ts` constructs Mathew's frozen bodies: `/v1/knowledge/drafts` gets **complete canonical** `{content, sources:[{sourceId,bytesBase64}]}`; `/v1/knowledge/:entryId/approve` and `/withdraw` get exact `{revision,contentHash}`. Internal action/context metadata never becomes a caller grant. Source bytes must be explicitly public/pre-reviewed and match every referenced source; the backend verifies actual hashes and rights/classification prerequisites. No public URL is fetched.
- The editor ignores legacy preloaded `sourceUploads` for Save. Only actual explicitly selected local source files can enable Save. Named approval identity/evidence are never editable form fields.

`createContentHttpIntegration` in `content/http-source.ts` consumes the frozen owner `@kandamkulathi/contracts/knowledge-authoring` schemas, `decodeKnowledgeAuthoringRecord` and `createDecodedContentAuthoringPort`. View reads use `GET /v1/knowledge/:entryId/authoring` with no query; action reads use only `?permission=edit|approve|withdraw`. View and action grants are independent. No caller roles, organization, scope or fabricated expiry are sent. Canonical decoding binds the current session actor, entry, scope, language, kind, revision and content hash.

The root must supply the **real approved transport**, approved Core/Companion origins and local-mode flag. The transport must cap raw response bytes at 65536 before JSON parsing and preserve actual web cookie/CSRF handling. The canonical codec additionally bounds decoded response/request JSON. Different or invalid approved origins return explicit Pending/unavailable without transport calls: no cross-origin credential workaround is implemented. The earlier bearer-only handoff is historical; the current server supports transaction-bound web guards. This module neither manufactures tokens/CSRF nor registers the server route. Root route registration must retain the owner's required same-transaction session guard. Native bearer wiring remains auth-owner Pending.

### Explicit local provenance files

Each registered source has one local file input. Select only public, pre-reviewed bytes with approved publication rights, never private patient/clinical data. WebCrypto SHA-256 hashes the actual selected bytes and must match that source's registered hash. Matching does not establish rights, clinical approval or server authority. No URL fetch, reconstruction, background upload, storage or filename transmission occurs. Every file must contain 1–48000 decoded bytes; empty, oversized, duplicate, unreadable and mismatched selections block Save. All registered sources are required.

Base64 is created only on explicit Save. The **complete actual UTF-8 JSON body**, including content/provenance/metadata/base64, must fit 65536 bytes; 48000 bytes per file is not a promise that a combined draft fits. A failed preflight sends nothing. Server 413 is a distinct terminal size rejection. Approve/withdraw send only CAS fields and need no files. Clear, refresh, grant loss/expiry, session/record/port replacement, mutation progress, page lifecycle suspension and unmount release owned bytes and remove filenames; stale hashing cannot repopulate a cleared selection. No browser file bytes or names are persisted. The synthetic authoring fixture runs under React StrictMode and uses canonical HTTP-shaped responses and codec, not opaque grant tokens.

Before dispatch the port reloads/revalidates the current source again. One scoped lane admits exactly one mutation attempt, disables duplicate dispatch and never retries a mutation automatically. The frozen DTOs contain no operation-ID field, so none is invented; if a subsequent backend contract requires stable operation identity, the trusted submit adapter must capture it once for that lane, not regenerate it on retries.

Only an exact `{status:"persisted",record:KnowledgeRecord}` body bound to the submitted full draft or CAS transition can progress to reloading. Candidate, malformed, mismatched-actor/hash/version/text/approval and extra-field responses cannot become success. A fresh authorized current read must exactly match that validated persisted record before the UI shows the new state; concurrent changes produce Conflict, not receipt-only success. Explicit 401/403/409/400/413/503 map to denied/conflict/invalid/oversized/pending; thrown/network/timeout/malformed outcomes after dispatch are Unknown. Mutation progress hides the old record/fields; terminal failures clear them and require explicit refresh/reconciliation. Abort/session/port/record/lifecycle invalidation fences all late replies, but does not pretend to cancel a possibly committed server operation.

Since package exports are parent-owned, this candidate imports its source directly using a relative path; no index/package change is required. Interface switching never translates source text, citation titles or reviewer names. Medical and final interface translation review remain absent.
