# Definition of Done

## A work package

- Named requirement/output/package/branch, owner/consumer and actual scope are clear.
- Implementation includes real integration, current-state/permission/negative/failure UX and applicable persistence/audit/jobs; no stub or UI-only business/security control.
- Reviewed schema/contracts/config/locale/ADR/runbook changes preserve old required native clients and controlled migration behavior.
- Relevant real checks were executed with candidate/environment/fixture/golden versions and honest results. Real RLS/race/native/provider claims have appropriate evidence; documentation CI is not their proof.
- Independent required senior review and physician/finance/privacy approval exist where applicable; no self-approved critical code.
- Defects are tracked, required blockers resolved and independently retested; impacted cumulative evidence is current.
- Handoff, docs/changelog/traceability and observation/reconciliation/rollback needs are complete. No secrets/private data enter code/public artifacts.

## A phase

All due outputs/variants and exact-candidate evidence pass the canonical campaign; company review and external status are explicit. Protected testing/capacity is preserved. No confirmed critical/high vulnerability, clinical/privacy/financial or acceptance blocker. Approved low-risk residuals need company owner/date and cannot remove a required feature. G1/G2 Pass permits milestone promotion only; not public release.

## The system release

Full R01–R38 acceptance, paid measured configuration/capacity/security/recovery, actual public Android/iOS/web/WhatsApp and required provider/listing eligibility, recorded role training/company ownership/support, prelaunch Go and safe postdeployment observation/reconciliation all pass. Submission/mock/internal build/dummy green script is not completion. “No possible bugs” is never a completion claim.
