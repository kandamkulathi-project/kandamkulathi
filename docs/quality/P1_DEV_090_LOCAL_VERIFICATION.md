## New local verification controls

- `pnpm verify:p1-local` requires the exact Node pin, a committed clean working tree/index and a feature/test branch accepted by the existing commit gate. Commit verification tooling first, then run the command without editing, fetching, staging or changing branches. It accepts **no skip, approval, arbitrary command or target overrides**.
- The command permits only default loopback public origins, local/stub mode and disabled live-send/payment flags. It refuses private dotenv/Worker overlays, unapproved public variables and server/provider credentials without logging their values. Those approved public inputs are recorded and rechecked. The command reuses the complete mandatory pre-commit gate, then scans full fetched history/index for secrets. Failed commands, missing evidence, changed source/index/refs or stale browser-run identifiers return nonzero and remain recorded as failure.
- The browser reporter hashes actual source bytes, HEAD/tree/index and all five current build roots **before and after** the browser campaign. Source/build drift, missing/empty build roots or unsafe paths make the browser command fail, even if test assertions passed. Iterative tests may bind a dirty worktree honestly; only the clean committed command can issue a local evidence bundle.
- Artifact inventory includes public/workspace output, Android/iOS JavaScript exports, and both Worker dry bundles. It identifies exact generated bytes; it does **not** prove installed native binaries, deployed Worker versions, native signing, reproducible cross-platform builds or schema/provider/config parity with a cloud environment.
- Each run creates a new ignored `private-evidence/P1-DEV-090/<UTC-and-UUID>/` directory with `manifest.json`, `browser-binding.json`, `SUMMARY.md` and separately hashed command logs. Failures are preserved; subsequent runs get new directories. The manifest identifies the candidate, source/config/lockfile hashes, platform/runtime, Git refs, command exit results and artifact hashes. It grants no canonical case or G1 acceptance.
- Browser metadata contains no test titles, error bodies, prompts, patient payloads or token values. Raw logs remain local and ignored. Restrict OS access and transfer only reviewed redacted evidence to the company-controlled store; `.gitignore` and file modes alone are not an access-control or encryption guarantee on Windows. Use synthetic inputs only. Never force-add evidence into Git.
- Normal E2E writes `test-results/p1-candidate-binding.json`. Application CI retains only that metadata for seven days using the existing pinned upload action. Hosted results and the current exact-head local run are recorded in PR #7; an earlier head's result cannot certify a revision. The runner does not create tags, merge, deploy, send messages, enable cloud resources or approve a release.

The new integrity checks have unit/CLI/browser negative controls for changed source, changed artifact bytes, missing/empty builds, symlink/traversal, dirty/staged/untracked sources, stale run IDs, zero/skipped/failed/retried browser results and attempted command/approval overrides. Real browser subprocess tests demonstrate that a passing assertion cannot hide source/artifact drift.
